# Sinyx Direction

We are not abandoning the Sinyx engine.

The engine remains:

- API on RapidAPI
- MCP package
- `format: "context"`
- docs and builder quickstart
- source extraction, chunks, citation, freshness, and quality

The homepage should stay engine-led because the engine is the asset.
The monitoring pilot remains the first focused income offer, not the entire identity of Sinyx.

## Current Bet

Sinyx remains a source-aware web context engine.
The first paid offer on top of it is a managed opportunity monitoring pilot:

> Watch public sources for tenders, RFPs, competitor changes, vendor updates, and important business signals. Send source-cited briefings.

## Why This Is The Bet

- Easier to sell as a concrete service than a generic API alone.
- Closer to revenue for agencies and service businesses.
- Can start manually before building a dashboard.
- Uses the existing Sinyx engine instead of replacing it.
- Creates future moat through watchlists, history, relevance feedback, and source intelligence.

## What We Are Not Doing Yet

- No full SaaS dashboard.
- No proxy spend by default.
- No generic agent brand.
- No more generic website expansion until we get buyer signals.
- No homepage identity swap that hides the engine.

## Decision Rule

After 10 real conversations:

- If buyers ask for the pilot, continue vertical.
- If builders keep buying API/MCP, keep builder path strong.
- If nobody cares, adjust the vertical before building more.

The direction is reversible. The engine stays valuable either way.
