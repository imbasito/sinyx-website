# Sinyx First-User Tracker

Use this to track whether the agent-context direction is producing real demand.

## Weekly Target

- 10 relevant builder conversations
- 3 visits or replies around `https://sinyx.me/start`
- 1 RapidAPI trial or real API request
- 1 clear objection to fix

## Conversation Log

Use `first-users.csv` for the working log. Keep this Markdown table for quick notes or summaries.

| Date | Person / Handle | Source | Use Case | Sent Start Link | Tried API | Objection / Signal | Next Action |
|---|---|---|---|---|---|---|---|
| YYYY-MM-DD |  | GitHub / X / Reddit / Discord / RapidAPI / Other |  | No | No |  |  |

## Objection Buckets

Use one bucket per conversation so patterns appear quickly:

- Positioning: does not understand why `context` is different.
- Trust: unsure about reliability, security, or uptime.
- Output: wants different fields, chunking, metadata, or citations.
- Integration: wants SDK, MCP setup help, examples, or docs.
- Price: RapidAPI plan, limits, or trial does not fit.
- Performance: speed, blocked pages, or extraction quality.

## Win Signals

Record exact wording when someone says:

- "This saves me from building extraction myself."
- "The MCP setup is useful."
- "The citation/freshness/quality fields help."
- "I can use this in my agent/RAG workflow."

## Recommended Next Step

After every 10 conversations, update one thing only:

- listing copy,
- `/start`,
- docs example,
- MCP setup,
- API response shape,
- pricing/limits.

Do not add random features until a repeated signal appears.
